Python Day 1｜六道复习题与核心代码
=================================

一、list 和 set 有什么区别？
---------------------------------

list 是列表：
1. 有顺序。
2. 允许出现重复元素。
3. 可以通过索引访问元素。

set 是集合：
1. 元素不能重复。
2. 不适合依靠位置取值。
3. 适合去重、求交集和求差集。

示例：

skills_list = ["python", "python", "rag"]
print(skills_list[0])

skills_set = {"python", "python", "rag"}
print(skills_set)

输出结果中，列表保留两个 python，集合只保留一个 python。
集合的显示顺序可能发生变化，不能使用 skills_set[0] 取值。


二、dict["key"] 和 dict.get("key") 有什么区别？
---------------------------------

假设有一个字典：

job = {
    "company": "百度",
    "city": "北京",
}

键存在时，下面两种写法结果相同：

print(job["company"])
print(job.get("company"))

区别发生在键不存在时：

job["salary"]

如果 salary 不存在，程序会产生 KeyError。

job.get("salary")

如果 salary 不存在，不会报错，而是返回 None。

get() 还可以指定默认值：

salary = job.get("salary", "面议")
print(salary)

记忆：
1. 确定键一定存在，可以使用 dict["key"]。
2. 键可能不存在，使用 dict.get("key") 更安全。


三、split() 返回什么类型？
---------------------------------

split() 返回 list 类型，也就是列表。

text = "Python,RAG,Docker"
skills = text.split(",")

print(skills)
print(type(skills))

输出：

['Python', 'RAG', 'Docker']
<class 'list'>

原始字符串不会被修改，split() 会创建并返回一个新列表。


四、为什么清洗文本时经常使用 strip()？
---------------------------------

strip() 用于删除字符串两端的空白，包括常见的空格、换行符和制表符。
它不会删除字符串中间的空格。

text = "  Python Developer  "
cleaned_text = text.strip()
print(cleaned_text)

输出：

Python Developer

相关方法：

text.strip()    # 清除两端空白
text.lstrip()   # 只清除左侧空白
text.rstrip()   # 只清除右侧空白

技能清洗中的常用写法：

cleaned_skill = skill.strip().lower()

这行代码先清除两端空格，再将英文字母转换为小写。


五、如何求两个技能集合的交集和差集？
---------------------------------

交集使用 &，表示两个集合共同拥有的元素。
差集使用 -，表示前一个集合有、后一个集合没有的元素。

my_skills = {"python", "git", "docker"}
required_skills = {"python", "pytorch", "rag", "docker"}

matched = my_skills & required_skills
missing = required_skills - my_skills

print("已掌握：", matched)
print("缺失：", missing)

注意差集有方向：

required_skills - my_skills

表示岗位要求但自己缺少的技能。

my_skills - required_skills

表示自己掌握但岗位没有要求的技能。


六、Python 为什么依赖缩进？
---------------------------------

Python 使用缩进表示一段代码属于哪个代码块。
一般统一使用 4 个空格，不要混用 Tab 和空格。

score = 80

if score >= 60:
    print("通过")
    print("可以进入下一阶段")

print("程序结束")

两个缩进的 print() 都属于 if 代码块。
最后一个没有缩进的 print() 不属于 if，无论条件是否成立都会执行。

错误示例：

if score >= 60:
print("通过")

这会产生 IndentationError，因为 if 后面的代码没有正确缩进。


Day 1 最核心的代码
=================================

1. 拆分字符串：

skills = text.split(",")

2. 清除空格并转换为小写：

cleaned_skill = skill.strip().lower()

3. 安全读取字典并提供默认值：

value = dictionary.get(key, 0)

4. 求集合交集：

matched = my_skills & required_skills

5. 求岗位要求中自己缺少的技能：

missing = required_skills - my_skills

6. 计算匹配率：

match_rate = len(matched) / len(required_skills)
print(f"匹配率：{match_rate:.1%}")

7. 使用字典统计次数：

skill_counts[skill] = skill_counts.get(skill, 0) + 1

8. 按出现次数从高到低排序：

sorted_skills = sorted(
    skill_counts.items(),
    key=lambda item: item[1],
    reverse=True,
)


综合示例：清洗技能并保持原始顺序去重
=================================

raw_skills = " Python,PyTorch, RAG,python, Docker ,RAG "

unique_skills = []
seen_skills = set()

for skill in raw_skills.split(","):
    cleaned_skill = skill.strip().lower()

    if cleaned_skill not in seen_skills:
        unique_skills.append(cleaned_skill)
        seen_skills.add(cleaned_skill)

print(unique_skills)

输出：

['python', 'pytorch', 'rag', 'docker']


复习时需要记住的易错点
=================================

1. set 可以去重，但不能依靠它保存列表中的原始顺序。
2. strip() 只删除字符串两端的空白，不删除中间的空格。
3. dict["key"] 在键不存在时会报错，dict.get("key") 不会。
4. 集合差集有方向，required_skills - my_skills 才表示缺失技能。
5. Python 使用缩进划分代码块，通常统一使用 4 个空格。
6. 函数定义的参数位置只能写参数名称，不能写 len(matched) 这样的表达式。


Git Day 1｜基础概念与实际操作
=================================

一、Git 的作用
---------------------------------

Git 是版本控制工具，可以记录代码每一次有意义的变化，帮助查看历史、比较修改、创建分支和恢复版本。
Git 与 GitHub 不相同：

1. Git 负责在本地管理版本。
2. GitHub 是用于保存和协作管理远程Git仓库的平台。
3. git commit 创建本地提交；git push 才会把本地提交推送到远程仓库。


二、初始化仓库前先检查目录
---------------------------------

使用以下命令查看当前目录：

Get-Location

进入Python学习目录：

cd "C:\Users\21855\Documents\python learning"

确认当前位置正确后再初始化：

git init -b main

git init 会在当前目录创建隐藏的 .git 文件夹，使当前目录成为Git仓库。

今天遇到的错误：第一次在 C:\Users\21855 中执行 git init，导致整个用户目录被Git扫描。
修复时只删除误创建的Git元数据：

Remove-Item -LiteralPath "C:\Users\21855\.git" -Recurse -Force

这条命令只适用于本次明确确认的错误路径，不能随意修改为其他宽泛目录。

经验：执行 git init、git add 和 git commit 前，先使用 Get-Location 确认当前目录。


三、查看Git状态
---------------------------------

git status

用于查看：

1. 当前位于哪个分支。
2. 哪些文件尚未被Git跟踪。
3. 哪些文件已经修改。
4. 哪些修改已经进入暂存区。
5. 当前是否还有内容需要提交。

常见状态：

Untracked files

表示文件尚未被Git跟踪。

Changes not staged for commit

表示工作区中的文件已经修改，但修改还未进入暂存区。

Changes to be committed

表示修改已经通过 git add 进入暂存区，等待提交。

nothing to commit, working tree clean

表示所有修改都已提交，工作区处于干净状态。


四、工作区、暂存区和本地仓库
---------------------------------

Git的基本流程：

修改文件 -> 工作区 -> git add -> 暂存区 -> git commit -> 本地仓库

工作区：
实际编辑文件的项目文件夹，例如 day01.py 和 day01笔记.txt。

暂存区：
用于选择哪些修改进入下一次提交。执行：

git add day01.py

会把 day01.py 的当前修改放入暂存区。

本地仓库：
保存正式的提交记录。执行：

git commit -m "提交说明"

会把暂存区中的内容保存成一条版本记录。

注意：git commit 只提交暂存区中的内容，不会自动提交所有工作区修改。


五、第一次添加和提交文件
---------------------------------

添加指定文件：

git add day01.py "day01笔记.txt"

创建提交：

git commit -m "完成 Python Day 1 学习"

查看简洁的提交历史：

git log --oneline

如果Git提示 Please tell me who you are，需要为当前仓库配置身份：

git config user.name "你的名字"
git config user.email "你的邮箱"

不添加 --global 时，配置只影响当前仓库。


六、查看文件修改
---------------------------------

查看工作区中尚未暂存的修改：

git diff

查看已经进入暂存区的修改：

git diff --staged

差异显示中：

1. 绿色加号 + 表示新增内容。
2. 红色减号 - 表示删除内容。
3. 如果进入分页查看界面，可以按 q 退出。
4. No newline at end of file 表示文件末尾缺少换行，不影响运行；可在文件末尾按一次回车修正。


七、创建和切换分支
---------------------------------

查看已有分支：

git branch

带星号 * 的是当前分支：

* main
  practice

创建并切换到新分支：

git switch -c practice

切换到已经存在的分支：

git switch practice

今天遇到的提示：

fatal: a branch named 'practice' already exists

原因是 practice 已经存在，却再次使用了带 -c 的创建命令。正确操作是：

git switch practice

记忆：

git switch -c 分支名    创建并切换到新分支
git switch 分支名       切换到已有分支


八、在分支中修改并提交
---------------------------------

在 practice 分支修改 day01.py 后：

git status
git diff
git add day01.py
git commit -m "在 practice 分支完成练习"
git log --oneline -3

日志中的：

HEAD -> practice

表示当前位于 practice 分支，HEAD 指向该分支的最新提交。


九、将practice分支合并回main
---------------------------------

切换回主分支：

git switch main

合并practice：

git merge practice

本次合并显示：

Fast-forward

表示main分支在practice开发期间没有新的分叉提交，因此Git可以直接把main向前推进到practice的最新提交，不需要解决冲突。

合并后的日志中：

HEAD -> main, practice

表示当前位于main，而且main和practice指向同一个最新提交。

最后检查：

git status
git log --oneline -3

当看到：

nothing to commit, working tree clean

说明合并完成且没有遗漏修改。
