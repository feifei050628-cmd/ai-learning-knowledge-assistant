============================================================
五、Path.glob() 的作用
============================================================

discover_learning_notes() 使用：

notes_directory.glob(pattern)

它会在指定目录中查找符合通配符规则的路径。

随后又使用：

if path.is_file()

只保留真实文件，避免同名目录被当成笔记。

最后使用 sorted()：

paths = sorted(...)

因为文件名中的 Day 编号统一为两位数字，所以按字符串排序也能得到正确顺序：

day01 → day02 → ... → day24

如果文件名不是固定两位数字，例如 day1、day2、day10，普通字符串排序可能得到：

day1 → day10 → day2

因此统一命名格式也有利于稳定排序。


============================================================
六、glob 规则和正则表达式的区别
============================================================

glob 用于发现文件：

day[0-9][0-9]笔记.txt

正则表达式用于严格解析文件名：

r"day(\d{2})笔记\.txt"

二者作用不同：

- glob：从目录中筛选候选文件
- regex：严格验证文件名并提取 Day 数字

正则中的关键部分：

- \d：一个数字
- {2}：前面的数字必须出现两次
- (\d{2})：捕获两位数字
- \.：匹配真实的小数点字符
- re.fullmatch()：要求整个文件名完全匹配
- re.IGNORECASE：忽略 day 的大小写

match.group(1) 得到捕获的数字字符串，例如 "25"。

int(match.group(1)) 把它转换为整数 25。


============================================================
七、为什么不存在目录或笔记时要报错
============================================================

discover_learning_notes() 对两种情况主动抛出 FileNotFoundError：

1. 学习笔记目录不存在。
2. 目录存在，但没有匹配到任何学习笔记。

这样做属于“尽早失败”。

如果程序在没有任何知识源的情况下继续执行，后面可能生成空预览、空向量或难以理解的检索错误。

在数据入口处给出明确错误，比让问题传播到后续向量化或检索阶段更容易排查。


============================================================
八、学习笔记的读取和清洗
============================================================

read_learning_note() 首先执行：

text = path.read_text(encoding="utf-8")

明确指定 UTF-8 可以正确读取中文，并避免依赖操作系统默认编码。

随后执行：

text = normalize_text(text.lstrip("\ufeff"))

\ufeff 是 UTF-8 BOM 在 Python 字符串中的表现形式。

某些编辑器保存 UTF-8 文件时会在开头加入 BOM。如果不清理，第一行标题开头可能包含不可见字符，影响标题、比较、哈希或检索文本。

lstrip("\ufeff") 只清理文本开头可能出现的 BOM。

normalize_text() 则复用 Day 24 的清洗逻辑，统一换行并处理多余空白。

清洗后如果文本为空，程序抛出 ValueError，防止空笔记进入知识库。


============================================================
九、学习笔记的统一文档结构
============================================================

每篇学习笔记被转换为一个字典：

{
    "document_id": ...,
    "source": ...,
    "title": ...,
    "text": ...,
    "char_count": ...,
    "category": "learning_note",
    "day": ...,
}

字段含义：

document_id
    文档的稳定编号，用于连接文档和文本块。

source
    可追踪的相对来源，例如 learning_notes/day25笔记.txt。

title
    文档标题。目前取清洗后文本的第一行。

text
    清洗后的完整笔记文本。

char_count
    清洗后文本的字符数量。

category
    知识源类别。学习笔记为 learning_note。

day
    学习天数，例如 25。

统一结构很重要，因为 build_chunks() 不需要知道文档来自 Markdown 基础资料还是学习笔记，只需要处理统一的文档对象。


============================================================
十、稳定 document_id
============================================================

学习笔记使用：

create_document_id(source)

source 采用稳定相对路径：

learning_notes/day25笔记.txt

只要 source 不变，多次读取同一篇笔记就会得到相同 document_id。

稳定 ID 的价值：

1. 可以判断文档是否已经存在。
2. 可以比较不同构建版本。
3. 可以让文本块稳定关联原始文档。
4. 后续可以据此做增量更新和删除。
5. 检索结果可以追踪回原始来源。

当前 ID 由来源路径决定，而不是由内容决定。

因此：

- 修改文档内容但路径不变，document_id 不变。
- 重命名或移动文件，source 改变，document_id 也会改变。

后续做增量索引时，还需要额外保存内容哈希，才能判断“同一文档的内容是否发生变化”。


============================================================
十一、合并基础资料与学习笔记
============================================================

merge_documents() 接收：

- reference_documents：基础资料
- learning_notes：学习笔记

基础资料原来没有 category 和 day，因此使用：

document.setdefault("category", "reference")
document.setdefault("day", None)

setdefault() 的含义是：

- 字段不存在时写入默认值
- 字段已经存在时保留原值

这样可以向后兼容 Day 24 的基础文档结构。

合并后的分类规则：

- 基础资料：category = "reference"，day = None
- 学习笔记：category = "learning_note"，day = 具体天数


============================================================
十二、为什么必须检查重复 ID 和来源
============================================================

合并后程序分别收集：

- 全部 document_id
- 全部 source

然后比较：

len(values) != len(set(values))

set 会去除重复值。

如果原列表长度与集合长度不同，说明存在重复。

重复 document_id 的风险：

1. 文本块可能关联到错误文档。
2. 使用字典建立索引时，后一个文档可能覆盖前一个。
3. 增量更新时无法唯一定位目标。

重复 source 的风险：

1. 同一知识源可能被重复导入。
2. 相同内容可能产生重复向量。
3. 重复结果可能占满 Top-K。

因此冲突应该在构建阶段直接报错，而不是静默继续。

3. 不会出现两份相似但行为不同的切块代码。
4. 测试职责更加清楚。

- overlap = 80

============================================================
十八、为什么不应该在每次 /ask 请求时重建
============================================================

扫描文件和切块相对便宜，但生成 767 个文本块的 embedding 会消耗明显时间和算力。

如果每次用户提问都重建知识库，会造成：

1. 请求延迟非常高。
2. 重复计算相同文本向量。
3. CPU/GPU 和内存浪费。
4. 多个并发请求可能同时写索引文件。
5. 读取到半写入文件的风险增加。

正确做法是把“知识库构建”和“在线问答”分开：

- 离线构建：文档变化时执行
- 在线检索：用户提问时读取已经构建好的索引

二十一、tmp_path 和 monkeypatch
============================================================

tmp_path 是 pytest 提供的临时目录夹具。

测试使用它创建模拟学习笔记和模拟输出文件，不会污染真实学习目录和真实知识库。

monkeypatch 用于在测试期间临时替换对象。

本次测试替换：

- load_all_source_documents
- EXPANDED_CHUNK_PREVIEW_PATH

这样 test_build_expanded_preview() 不需要读取全部真实笔记，也不会覆盖真实 expanded_chunk_preview.json。

测试结束后，pytest 会自动恢复被替换的属性。

这使测试具备：

- 隔离性
- 可重复性
- 运行速度快
- 不依赖真实用户数据

============================================================
二十八、当天知识点总结
============================================================

1. 配置路径时应使用 pathlib.Path，避免手工拼接分隔符。
2. PROJECT_DIR.parent 可以得到 rag_project 的父目录。
3. Path.glob() 可以按通配符规则发现文件。
4. Path.is_file() 用于排除同名目录。
5. sorted() 让文件处理顺序保持稳定。
6. 固定两位 Day 编号可以保证字符串排序正确。
7. glob 负责筛选候选文件，正则负责严格解析。
8. re.fullmatch() 要求整个文件名完全符合规则。
9. 正则捕获组可以提取 Day 编号。
10. encoding="utf-8" 对中文文件非常重要。
11. UTF-8 BOM 在字符串中表示为 \ufeff。
12. lstrip("\ufeff") 可以清理文件开头的 BOM。
13. 清洗后的空文档应尽早拒绝。
14. 不同知识来源应转换成统一文档结构。
15. source 应保存稳定、可追踪的相对路径。
16. document_id 应在多次构建之间保持稳定。
17. 路径稳定 ID 与内容哈希解决的是不同问题。
18. setdefault() 只在字段不存在时设置默认值。
19. category 可以区分 reference 和 learning_note。
20. day 可以支持按学习阶段过滤知识。
21. 合并文档时必须检查重复 ID 和来源。
22. len(list) 与 len(set(list)) 可以检测重复值。
23. 通用切块逻辑应该复用，而不是重复实现。
24. 文档级元数据需要继续传递到文本块级别。
25. document_id 可以作为文档与文本块之间的连接键。
26. 字典索引可以高效地通过 ID 查找文档。
27. expanded_chunk_preview.json 是派生数据，不是原始事实来源。
28. ensure_ascii=False 让 JSON 中文保持可读。
29. indent=2 方便人工审查 JSON。
30. min、max 和平均长度可以帮助检查切块质量。
31. 当前扩展知识库包含 28 个知识源。
32. 当前扩展知识库包含约 32 万字符。
33. 当前扩展知识库产生 767 个文本块。
34. 切块预览不等于向量知识库。
35. 更新预览不等于正式检索已经更新。
36. 新增笔记后目前必须重新运行 note_importer。
37. 不应该在每次 /ask 请求中重建向量库。
38. 离线索引构建和在线问答应当分开。
39. 后续增量更新需要保存内容哈希。
40. tmp_path 可以隔离测试产生的文件。
41. monkeypatch 可以临时替换函数和路径。
42. 测试不应该覆盖真实知识库文件。
43. 参数化测试中的每组参数都是独立用例。
44. --basetemp 可以绕开系统临时目录权限问题。
45. py_compile 只能检查语法，不能发现全部运行时错误。
46. NameError 通常表示运行时使用了未定义或未导入的名称。
47. 编辑器标签白点表示文件尚未保存。
48. 模块文件必须放在与导入路径对应的包目录中。
49. 回归测试用于确认新功能没有破坏已有行为。
50. warning 与 failed test 必须区分处理。
